# Hamlet — Professions, Sickness & House Upgrades (Design Spec v2)

Extends `2026-10-10-hamlet-design.md` and `state-contract.md`. All numbers live in `src/config.js`
(already updated: new RESOURCES, BUILDINGS, 5 HOUSE_LEVELS, sickness/supply/tools/deer constants).

## 1. Food variety (replaces the old `bread` need)
- FOODS = bread, meat, fish, berries. When eating, a villager takes the first food in FOODS order
  that its household has NOT eaten yet today and the storage has; otherwise any food in FOODS order.
- Each house tracks `foodsToday: string[]` (distinct foods its residents ate since last midnight).
- Needs: `variety2` = foodsToday.length >= 2, `variety3` = >= 3. `food` unchanged (no resident starved).

## 2. House upgrades (manual + auto, 5 levels)
- House fields: `autoUpgrade: boolean` (default true for new and migrated houses).
- `upgradeStatus(state, house)` → `{ level, nextLevel|null, needs: [{ key, name, met }], cost, missing, canUpgrade, reason }`
  — needs/met evaluated against the NEXT level using the house's current `needsMet` (refreshed by evaluateHouse,
  which now also runs once per game-second for houses so the UI is live). `missing` = cost the storages cannot cover.
  `canUpgrade` = all next-level needs met && not already upgrading && level < 5. Materials need not be in stock
  (haulers wait for them) — but `missing` is shown.
- `requestUpgrade(state, houseId)` → `{ ok, reason }`: if canUpgrade, start upgrading now (same mechanism as today:
  `upgrading = true, needed = copy(upgradeCost), incoming = {}, progress = 0`, build time UPGRADE_BUILD_TIME).
- `setAutoUpgrade(state, houseIdOrNull, on)` — null = every house.
- Midnight auto-upgrade only for houses with `autoUpgrade` true.
- On upgrade completion push event `บ้านอัปเกรดเป็น<name>แล้ว` and append `{ t: time, x, z, kind: 'upgrade' }` to
  `state.fx` (render consumes & clears — keep max 20).

## 3. New jobs (BUILDINGS[type].job)
| job | behaviour |
|---|---|
| `fish` | Placement requires water within `radius + NEAR_WATER_DIST` (and footprint not on water) — reason 'ต้องวางติดแหล่งน้ำ'. Worker finds a shore point (land cell adjacent to a water cell) within FISH_RADIUS of the building (deterministic search, cache on building as `b.shore = [{x,z}]` up to 12 points), walks there, `produce` for cfg.time, carries output to nearest storage. Role 'worker'. |
| `ranch` | Worker walks to a random point within 0.6 × radius of the building (inside the pen), `produce` cfg.time; output alternates between cfg.outputs[0] and [1] using `b.cycle` counter. |
| `hunt` | `state.animals` holds deer (see §5). Worker reserves the nearest alive unreserved deer within HUNT_RADIUS of the building, walks toward it (target re-read each step since deer move) until within HUNT_SHOT_DIST, then `hunt` work cfg.time; deer removed; carry output to storage. No deer → wait 3. |
| `gather` + `keepNode` | Herbalist: same as gather on trees but the node amount is not reduced and the node is not reserved exclusively (many herbalists may share). |
| `gather` on `ore` | Ore nodes generated by terrain (see §6); otherwise like quarry. |
| `doctor` | Service building with supply 'herbs': if its `stock.herbs < SUPPLY_MAX/2` and a storage has herbs, a doctor fetches up to CARRY_MAX herbs into `b.stock`. Else if a sick villager is within serviceRadius and `b.stock.herbs >= HERBS_PER_HEAL`, reserve that patient (`patient.healer = v.id`), take 1 herb from b.stock, walk to the patient (re-read position), `heal` work HEAL_TIME → patient.sick = false. Else staff the building (like service). |
| `market` | Supply 'cloth': vendors keep `b.stock.cloth` topped up to SUPPLY_MAX from storages, otherwise staff the building. |
| `process` (weaver, blacksmith) | unchanged mechanism. |
Service coverage rule (religion/entertainment/health/clothing): built + staffed (worker within SERVICE_STAFFED_DIST, or sleeping as today) + within serviceRadius; additionally for buildings with `supply`, `b.stock[supply] > 0`.
At midnight each house whose level needs `clothing` and is covered by a market consumes CLOTH_PER_HOUSE_PER_DAY from that market's stock (fractional ok); `needsMet.clothing` is true only if the market had stock.
Service buildings with `supply` get `stock = { [supply]: 0 }` when built.

## 4. Sickness
- Villager fields: `sick: boolean`, `sickDays: number`, `healer: villagerId|null`.
- At midnight each healthy villager falls sick with p = SICK_CHANCE_PER_DAY × (SICK_HUNGRY_MUL if their home starvedToday) × (SICK_COVERED_MUL if home has health coverage). Event: `ชาวบ้านป่วย N คน` (aggregate).
- Sick villagers: drop their job slot temporarily (jobId kept but planNext treats them as off-duty): go home and `rest` (like sleep) — homeless sick villagers rest at the townhall. Walk speed × SICK_SPEED_MUL. They still eat.
- Each midnight sick: sickDays++; if sickDays >= SICK_LEAVE_DAYS → they leave (event `ชาวบ้านป่วยหนักย้ายออกไป 1 คน`).
- Healed: sick=false, sickDays=0, event optional.
- summary adds `sick` count.

## 5. Animals
- `state.animals = [{ id, kind: 'deer', x, z, tx, tz, wait, reserved: villagerId|null }]`, created in createWorld (DEER_COUNT deer at random forest points: within 6 m of a tree node, not water, away from spawn).
- Each step deer walk toward (tx,tz) at DEER_SPEED; when reached, wait 2–6 s, pick a new target within 15 m that is land; flee: if a non-hunter villager is within 8 m, pick a target away from them.
- Every DEER_RESPAWN_SEC, if fewer than DEER_COUNT deer, spawn one at a random forest point near the map edge.
- Sheep are render-only (no sim state).

## 6. Ore nodes (terrain.js)
- generateNodes adds up to NODE_COUNTS.ore 'ore' nodes on land where height >= ORE_MIN_HEIGHT × MAX_HEIGHT, min gap 6 m, > SPAWN_CLEAR_RADIUS from spawn, amount NODE_AMOUNT.ore. If high ground is scarce, relax to the highest 15% of land. Deterministic.

## 7. Tools
- At midnight, for each built production/resource building with ≥1 worker, take TOOLS_PER_BUILDING_PER_DAY tools from the nearest storage that has them (building id order). Success → `b.tooled = true` for the next day, else false.
- `gather`/`produce`/`hunt` work durations at a tooled building are multiplied by (1 − TOOL_SPEED_BONUS).

## 8. Save migration
- save version 2. deserialize accepts v1: add `animals` (generate deer), `fx: []`, house `autoUpgrade: true`, `foodsToday: []`, villager `sick: false, sickDays: 0, healer: null`, service supply stocks; regenerate ore nodes? No — keep v1 nodes (no ore) and append ore nodes from generateNodes filtered to kind 'ore' with fresh ids above max id.
- Old `needsMet.bread` ignored.

Ore node visuals (rock with rusty streaks). Sheep (wander inside built sheepfarm pens, render-only) and deer (from state.animals) as instanced animated animals. Upgrade sparkle effect from state.fx.
